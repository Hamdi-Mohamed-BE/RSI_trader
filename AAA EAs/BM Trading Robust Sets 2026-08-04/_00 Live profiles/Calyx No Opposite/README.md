# Calyx No Opposite (2026-11-17)

Owner: "build the no opposite trade rule into the EAs and add to profile along side with weekend hold".
Reason: FundingPips support (2026-11-17, AI assistant): a buy and a sell on the same symbol at the same time is forbidden hedging, with no
exceptions, even from two independent strategies. It is checked at the end of the evaluation and before each reward.

## Rule (input `InpCalyxNoOpposite`, the installers ask ON / OFF, default OFF = the tested behaviour)
- ON: a NEW market entry or pending order is refused while any position on the same symbol is open in the opposite direction.
  "Any position" means any EA, any magic, manual trades too.
- Same-direction stacking, closes, partial closes, SL/TP changes and order deletions always pass.
- No-guard EAs: the check and the send run under one account-wide lock file (`Common\Files\CalyxNoOpposite-<login>.lock`), so two EAs
  cannot open opposite sides in the same moment.
- `CNO_Tick` (wrapper OnTick, at most once per second):
  - deletes the EA's OWN pending orders that face an opposite open position;
  - closes the EA's OWN position if it became the newer side of an opposite pair (a pending fill in the same second).
  - It never touches other EAs' or manual orders and positions.
- Guarded EAs (FTMO 1-Step guard): the same check runs inside the guard's existing lock. Those guards refuse pending orders, so only the entry
  check applies.
- OFF: `CalyxNoOppOrderSend` is exactly `::OrderSend` / `::OrderSendAsync`; nothing else runs.

## Files
- `CalyxNoOpposite.mqh`: the rule.
- `CNO_Trade.mqh`: generated by `make_trade.py` from the isolated MetaEditor's standard Trade.mqh. The only change is that
  CTrade::OrderSend goes through CalyxNoOppOrderSend. Hashes are in CNO.json.
- `test/`: native harness (`CNO Test.mq5`, `run_test.py`, RESULTS.json). Rule ON: 11/11 checks pass; rule OFF: 11/11 (everything goes through).
- `parity/`: rebuilt Best 1-Step no-guard wrappers vs the tested EX5s (PARITY.json). Native Model 4, 2026-08-16 -> 11-16, each EA alone:
  - Rule OFF = the tested EX5 trade for trade on 8/8. UK100 has no earlier no-guard build of this wrapper.
  - Rule ON = OFF on 9/9 (an EA alone never faces an opposite position).
  - 3 Way Gold's first run differed by one fill price; rerunning the same old EX5 reproduced the new value (tester noise). That first run is kept in `parity/first-run/`.

## Wired into
Best 1-Step (`../Best 1-Step/build.py`, both BATs):
- No-guard: all 9 wrappers recompiled with the shim.
- Guarded: the guard checks inside its lock.
- Both installers: question "No opposite trades on the same symbol? ON or OFF [OFF]", parameter `-NoOpposite ON|OFF`.

Other profiles are unchanged.

## Limits
- The rule works per account. It cannot see positions on your other accounts; FundingPips also forbids opposite trading ACROSS accounts.
- With the rule ON, what happens after a refused entry depends on the EA. Some drop the signal; some may retry while it is still valid and
  enter after the opposite trade closes. The simulation assumed skip.
- Simulation (Multi Firm Funded 2026-11-17, Addendum 3): ON skips about 7% of trades and about 4% of R for the 9-EA roster.
