## Eligibility and overrides

  website reference only and is not optimised.
- Raw 3y gate: B passed; **A and C failed**. The user explicitly asked to optimise each sub-bot, so A and C are optimised

## Search EA and parity
One search EA with a generated case table (one row per configuration) run through MT5's complete optimiser over the
case index; each pass writes its own deal ledger. Up to three independent module slots run in one test (own magic,
own 1% risk) for combinations. With `InpRetryClosed=false` and each module's raw case, the search EA must reproduce the
raw 3y native trades and cash exactly (A, B, C) before searching. In the search, `InpRetryClosed=true`: a trailing-stop
update rejected because the market is closed is retried on the next tick (fix for the raw study's disclosed daily-break
rejections). This is an execution fix fixed before searching, not a fitted rule.

## Staged beam search (development only)
Per module, stages in order (A/B: all; C: the applicable ones marked C):
1. Timeframe: M5, M15, M30, H1, H4. (M1/M3 excluded: sub-hour noise dominated by spread for these bar-count rules; D1
   excluded: the 600-bar EMA seed and 480-bar range exceed the 180-day warm-up.) C: not applicable (calendar).
2. Entry: next quote after signal close; confirmation candle; limit retest 0.1/0.25/0.5 ATR; stop entry 0.1/0.25/0.5 ATR
   (pending lifetime 4 bars). C: entry hour — session open / 07:00 UTC / 13:30 UTC.
3. Stop (A/B/C): ATR 0.75/1/1.5/2/2.5/3/4; percent of price 0.1/0.2/0.5%; 5-bar swing or 20-bar structure + 0.1 ATR.
   C uses D1 ATR; C adds "no stop" is NOT allowed (sizing needs a stop).
4. Stop management (A/B/C): none; breakeven at 0.5/1/1.5R; raw trail (initial distance) from 0.5/1/1.5/2R; ATR trail
   from 0.5/1/1.5/2R at 1/1.5/2/3 ATR; percent trail 0.1/0.2/0.5%; EMA20 trail from 1R. Trails tighten only, updated on
   closed bars of the module timeframe.
5. Exit (A/B/C): fixed target 0.5/0.75/1/1.25/1.5/2/2.5/3/4/5/6R; no target; time exit after 8/16/32 bars; flat at the
   end of each trading day; partial 50% at 1R with the rest as configured. C: exit day +1/+2/+3 replaces time exit.
6. Session of entry (A/B): all; Asia 00–08 UTC; London 07–16 UTC; New York 09:30–16:00 local; overlap 12–16 UTC;
   NY open 09:30–11:00 local (US DST calculated by calendar).
7. Direction (A/B): both / long / short. C stays long (the documented effect is positive returns).
8. Filters (A/B/C): none; EMA200 bias on the module timeframe; H4 EMA50 bias; ADX14 ≥ 20; ATR percentile 20–80 over
   the prior 100 readings; spread ≤ 0.1 ATR; D1 EMA50 bias.
9. Management (A/B): weekday exclusion none/Mon/Fri/both; max 1/2/3 entries per day or unlimited; hold overnight and
   weekend (raw) / flat daily / flat before the weekend; season all / Q4 only / Jul–Dec only.
   C: season all / Q4 only / Jul–Dec only; weekday of entry exclusions none/Mon/Fri.
10. Signal logic: A lookback 12/24/48, threshold 0/0.25/0.5/1 ATR, EMA 50/100/200; B range 240/480/960, breakout
    20/40/60/120, edge 5/10/20/50%, volatility window 0 (off)/20/50/100; C entry day −3/−2/−1, exit day +1/+2/+3.

**Beam:** at every stage keep the top 3 by the BEST score and the top 3 by the PROP score (≤ 6 distinct leaders), then
apply the next stage's patches to every leader. Every case (including duplicates, zero-trade and rejected cases) is
counted for the deflated Sharpe. This is a broad staged beam search, not an exhaustive grid or a global optimum.

**Clean case:** no failed entry/close/modify/cancel, no margin stop-out, no invalid-risk row, ledger reconciles to the
native result. **Eligible (development):** clean, ≥ 60 trades (C: ≥ 20), net > 0, PF ≥ 1.15.

**BEST score** (never return alone): eligible → (PF − 1) × √trades ÷ (1 + equity DD% ÷ 10); clean but ineligible and
net ≤ 0 → −1 − |net|/10,000 − DD/100; otherwise −1000.

**PROP score** (the user's prop objective): among eligible cases of the same stage batch, the mean of percentile ranks
of (1) win rate, (2) Sharpe (site definition: daily closed-trade returns, every calendar day, × √365), (3) maximum
consecutive winning trades. Ineligible cases rank below all eligible cases. No drawdown term is added (the user named
the three measures); drawdown is reported next to every result.

## Plateau, validation and freezing
- Finalists: top 3 distinct eligible cases per objective after the last stage.
- Plateau: perturb the three most sensitive active numeric settings (from stop distance, target R, trail distance,
  entry offset, signal parameters) by −20% / 0 / +20% (27 cases, development, Model 1). Pass: ≥ 2/3 of neighbours
  positive and clean, median PF > 1, at least two genuinely active axes.
- Validation (Model 4): each plateau-passing finalist once. Eligible: clean, ≥ 30 trades (C: ≥ 12), net > 0, PF ≥ 1.15.
  BEST pick = highest BEST score; PROP pick = highest PROP score among validation-eligible finalists of that objective.
- Frozen picks then run once on the recent check and once on the older holdout (Model 4, same eligibility). No
  retuning after validation. Verdict per module/objective: QUALIFIED / REJECTED_<stage>.
- The user asked for results on the website periods regardless; the frozen picks are therefore also run on 6m/1y/3y/5y
  and reported **with their verdict**. A rejected pick shown on website periods is not a promotion.

## Combination
- BEST trio = A-best + B-best + C-best; PROP trio = A-prop + B-prop + C-prop, run together natively (independent slots,
  1% each). If some modules are rejected, the survivors-only combination is also reported. Combinations are run on
  validation, recent, older holdout and the website periods. No combination weights are fitted.

## Robustness (mandatory for the best versions)
On the BEST trio and PROP trio native Model 4 5-year trades: `calyx_pipeline.py` (10,000 block-bootstrap paths,
block 5, deflated Sharpe with ALL tried configurations, trade-order reshuffle, random removal, cost stress using the
measured median spread only if available, daily/total loss-limit breach frequencies at 5%/10%). Policy for forward-test
eligibility: return p05 > 0, PF p05 > 1, DSR ≥ 95%. Historical resampling is not a probability guarantee.
